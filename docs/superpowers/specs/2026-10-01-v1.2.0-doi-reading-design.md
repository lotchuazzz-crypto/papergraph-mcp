# v1.2.0 DOI entry and dependency reading

This records engineering choices made while executing the handoff, not a claim
that the user approved a detailed interface specification. Preserve the first-use
batch and all original changes. No subagents, commits, push, PR or release.
No new dependencies; Python >=3.10; published version/pin stays 1.1.7.

## DOI entry (second batch)

- `discover_doi_paper(doi)` / CLI `discover-doi DOI`: exact DOI lookup only,
  using existing identity normalization, provider record conversion and outcome
  vocabulary. Crossref supplies identity/metadata and unverified full-text links;
  OpenAlex locations supply access/version/license reports. Queries are bounded
  and failures are separate from absence of candidates. No full-text requests.
- DOI identity, metadata, location candidates and import state are separate.
  DOI conflicts block import; ambiguous input contacts no providers. Title matching
  cannot authorize an import. OA reports are evidence, not verified PDF identity.
- `workspace_import_doi_candidate(doi, candidate_id, confirmed=False)` / CLI
  `import-doi-candidate WORKSPACE DOI CANDIDATE --confirm`: re-discover the
  reviewed candidate, then import through existing PDF extraction/atomic import.
  Use this selected-candidate path for explicit user selection among alternatives.
  External references are still review-plan-only.
- User subsequently confirmed root-paper behavior: “直接下载就好”.
  `workspace_add_doi_paper(doi)` / CLI `add-doi-paper WORKSPACE DOI` imports
  automatically when one exact-identity provider-reported OA direct PDF candidate
  is eligible. Multiple versions/locations require selection; metadata, unavailable
  sources and conflicting identities never cause an import. This root authorization
  is not permission to recursively download references.
- Only provider-reported OA direct PDFs are downloadable. Other links remain
  visible for review, with local-PDF fallback. No HTML scraping, login, cookies,
  paid API, credential acquisition or paywall bypass.
- Download uses HTTPS/443, credential-free URLs, public-only DNS pinned to the
  connection, TLS hostname verification, checks at every redirect (max five),
  no environment proxy, 50 MiB decoded content limit, PDF MIME/signature checks,
  socket timeout and elapsed deadline. Content-addressed source storage and
  provenance receipts live adjacent to the workspace, with no cache cleanup.
- Receipt includes provider source, reported version/license, final URL, redirects,
  bytes/hash and explicit `content_identity_verified: false`. PDF extraction does
  not prove correspondence to DOI or equality to the published version.

Reference contracts checked against official documentation on 2026-10-01:
[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/),
[OpenAlex locations](https://help.openalex.org/data/locations/).
Services may require keys or return rate limits; report provider unavailability
rather than claiming no public full text exists. No keys are acquired or logged.

## Dependency reading (third batch)

First reproduce the shared-dependency failure using real extracted proof evidence:
A uses B,C; B uses D; C uses D. Preserve top-down exploration semantics. Replace
reversed preorder with dependency-first DFS postorder, retaining each result once.
Direct mode includes immediate dependencies in `bottom_up` and the additive
`direct_dependencies` field without traversing their proofs. The legacy direct
`top_down` remains the selected root only. Correcting direct `bottom_up` from
root-only to dependency-first is an intentional behavior fix; CLI regression
checks the corrected order and excludes indirect dependencies.
Cycles/self-loops are explicit; no cycle-containing path is called topological.
Keep legacy keys, add order status, evidence traces and limits; downstream readers
can still explore top_down while prerequisite order is available in bottom_up.
Paper map candidate summaries and Markdown reading reports expose order status,
dependency-first result IDs and cycle explanations. Existing root-first exploration
routes/queue positions retain their meaning and are not called topological orders.

`workspace_get_dependency_reading` / CLI `get-dependency-reading WORKSPACE PAPER`
is the read-only overview for paper/result selection. Reuse existing paper map
main-result candidates; never silently select the first heuristic as definitive.
For user-selected targets expose statement graph separately from direct/recursive
proof-local evidence, reading path and external import plan. No proof verification,
implicit dependency inference or downloads. Unknown proof/labels stay visible.

## Legacy-consumer conflict audit (additional user request)

- Reproduced: bundle `completeness_check.circular_deps` was hard-coded empty
  even for extracted A/B and self cycles. It now reports source-backed cycle
  witnesses, acyclicity and the exported-index assessment scope. `self_containment`
  is lowered for observed cycles and is explicitly not mathematical completeness.
- Reproduced: Evidence Triage and report logic-chain rendering constructed edges
  from root-first exploration items (including proof targets and self-pairs).
  They now consume actual `edge_evidence` with source/target result IDs. Old maps
  without the additive evidence field only contribute explicit non-self local
  result relationships; route position alone cannot establish a dependency.
- Context warnings now include cycle/coverage warnings already in its path preview.
  Queue positions retain exploration semantics; `get_reading_queue` adds current
  dependency-order status and cycle witnesses separately. Direct queues include
  direct dependencies, without expanding their dependencies.
- Paper Map summaries and report/triage expose cycle-blocked order. Cross-paper
  plans retain citation/context exploration and explicitly say their sequence is
  heuristic, not topological; local-cycle warnings and order metadata propagate.
  Cross-paper citation cycles are not reclassified as mathematical proof cycles.
- Re-import still preserves queue IDs/items/positions, sessions/checkpoints,
  and its existing `reimport_review_required` flags. Existing source-change behavior
  marks retained checkpoints blocked for review (their status is not frozen).
  No schema migration, queue
  reorder or state reset is introduced. All schema version constants stay unchanged.
- Statement-reference recursion used by both the legacy graph and Workspace was
  also replaced with an order-preserving iterative traversal after reproducing
  stack overflow on a long cyclic chain. Reachability (including the root when
  cyclic) remains distinct from prerequisite ordering and proof-local dependency.
- Unknown labels/proofs and external blockers stay visible; external plans do not
  download. Cycles with an acyclic branch expose all reachable nodes for exploration
  but return no purported full prerequisite order. No implicit edges are added.

Coverage limits: cycle witnesses are not exhaustive enumeration of every possible
cycle. Result reading paths cover the selected reachable proof graph. Reading
bundle completeness examines its exported dependency index (the legacy export
limit of 100 results remains); it is not a whole-paper mathematical proof audit.

## Local first-use findings incorporated

The authorized real DOI exercise exposed three existing PDF/overview problems:
uncited bibliography entries had no direct source spans and could block an entire
PDF import; grouped references shared one record and could cross-assign a later
entry's identifier; the first-span SQL join used position 1 although positions
start at 0, distorting early-result candidate signals. Regressions reproduced each.

PDF bibliography extraction now splits line-start bracket labels within source
blocks and retains each entry's exact text offsets and block/page evidence. Added
source-span copies preserve existing result/proof indices and traceability checks.
Main-result ordering uses position 0. These changes do not infer proof relations,
identify unknown references, or extend external-download authorization. References
continued across PDF blocks and ambiguous/repeated result headings still require
coverage warnings/review; no complete PDF parsing claim is made.

## Approved bounded quality follow-up

The user subsequently approved four ordered improvements, recorded with actual
results in `../plans/2026-10-01-v1.2.0-bounded-quality.md`:
explicit author-declared introductory correspondence as proof navigation, formal
PDF heading recognition, truthful PDF summary/metadata presentation, and nested
external-blocker evidence propagation. This does not introduce mathematical
equivalence checking, implicit dependency inference or external downloads.

Correspondence is persisted through existing source-backed evidence edges; both
results remain distinct and the actual proof owner is retained. Own proofs have
priority. Duplicate/missing/cyclic targets or an engineering limit of 8 hops stop
navigation. Reading order remains bounded to extracted local evidence.

PDF evidence counts/import state are additive to legacy LaTeX graph counters.
Provider metadata is separately attributed, with a validated content-addressed
receipt/index beside the workspace, no DB migration or overwrite of user sources.
Formal duplicates remain ambiguous; discussion mentions are not extra declarations.
Bounded cross-page statement continuation retains both source locations. Triage
preserves observed citation keys, raw evidence, confidence and review state.

The 8-hop and four-adjacent-span limits, receipt format and additive field names
are engineering choices within the approved goals, not previously user-approved
interface specifications. Final packaging/cross-version/real-paper results and
environment limits are in the linked plan; the published pin still remains 1.1.7.
