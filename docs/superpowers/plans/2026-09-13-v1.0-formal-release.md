# v1.0 Formal Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release PaperGraph as `1.0.0` with a stable evidence-first reading workflow, polished README, reproducible first-use commands, and a maintainer release checklist.

**Architecture:** This is a stabilization release. Runtime behavior stays unchanged; implementation updates tests, active version pins, documentation, onboarding instructions, and release metadata. README becomes the primary concise product homepage, with details moved behind existing collapsible reference sections and deeper docs.

**Tech Stack:** Python packaging through `pyproject.toml` and `uv.lock`; pytest; Markdown docs; GitHub Actions; MCP stdio launch through `uvx`.

## Global Constraints

- Release version is `1.0.0`; release tag is `v1.0.0`.
- No new extraction logic.
- No new MCP tools.
- No new CLI commands.
- No database migrations.
- README active install commands must use pinned `uvx --from git+https://github.com/lotchuazzz-crypto/papergraph-mcp.git@v1.0.0`.
- README CLI examples must use current argparse shape: `papergraph-mcp <command> --workspace ...`.
- Historical release notes, specs, and plans may retain old version strings as history.
- Workspace databases must still be documented as outside the Git repository.
- Evidence boundaries must keep saying PaperGraph does not verify proofs, infer hidden prerequisites, or perform semantic theorem matching.
