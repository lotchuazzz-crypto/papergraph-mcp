## Shared wire contracts

Use plain JSON-compatible dictionaries consistent with the repository. New
normalization records have this exact shape (invalid input has null canonical
and identity values; raw is always retained):

```python
{
    "kind": "doi", "raw": "https://doi.org/10.1000/Example",
    "canonical": "10.1000/example", "identity": "doi:10.1000/example",
    "version": None, "valid": True, "exact_eligible": True, "warnings": []
}
```

Field evidence has `field`, `value`, `evidence_id` (nullable), `excerpt`,
`rule`, `confidence`. Group members have `provider`, `record`, `record_key`;
record keys are SHA-256 of canonical JSON including provider, not input index.
Group output has `group_key`, `identifiers`, `members`, `target`, `conflicts`.
`target` always remains a dictionary: conflicted groups expose only a metadata
display target without DOI/arXiv/path fields; never a synthesized acquisition
target. `conflicts` entries have `code`, `field`, `values`, `evidence_refs`.

Assessment entries use the spec's fields. `matched_fields` entries have `field`,
`relation`, `query_value`, `candidate_value`, `evidence_refs`; missing-fields
entries have `field` and `side` (`query` or `candidate`). All reason lists are
deduplicated and lexically sorted. Next actions are lists of action-code strings.

`summary` preserves old counts and adds `total_candidate_count`,
`returned_candidate_count`, `truncated`, `blocking_conflicts`. The last field
contains conflict summaries from the full result set, not only returned rows.
Auto-selection output uses the existing selector keys `eligible`, `reason_codes`,
`policy_version`, with `candidate`, `target`, `identity_target` only on success.
