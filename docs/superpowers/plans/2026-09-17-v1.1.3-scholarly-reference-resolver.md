# v1.1.3 Scholarly Reference Resolver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add proactive scholarly reference search for blocked external references, ranking Crossref/OpenAlex/arXiv candidates while applying durable resolutions only through explicit user intent.

**Architecture:** Add a focused `reference_search.py` domain module plus small provider modules under `src/papergraph/reference_providers/`. `Workspace` owns persistence and orchestration, while provider adapters normalize external records into deterministic candidate inputs. Reports and triage consume persisted search summaries without triggering network calls.

**Tech Stack:** Python 3.10+, SQLite, `httpx`, existing PaperGraph `Workspace`, MCP server wrappers, CLI subcommands, pytest.

## Global Constraints

- Do not use subagents for this implementation.
- Use TDD: write focused failing tests before production code for each behavior.
- Default deterministic tests must use mock providers and must not require network access.
- Search, ranking, caching, and report rendering do not require confirmation.
- Applying a candidate, importing, overwriting, downloading, or recursive expansion requires explicit user intent.
- Published-paper metadata through Crossref/OpenAlex is first-class; arXiv is not the only resolver.
- Search output must explain boundaries such as old/undigitized works, metadata-only records, paywalls/restrictions, ambiguity, version uncertainty, provider failure, and unsupported source types.
- Keep v1.1.2 Reference Import Closure as the only durable resolution/import path.
