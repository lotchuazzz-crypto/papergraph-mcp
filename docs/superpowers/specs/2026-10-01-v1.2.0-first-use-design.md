# v1.2.0 first-use corrections

Approved direction: fix first-use problems, then improve DOI/published-paper entry,
then dependency-reading usability. Develop and verify locally; do not push or release
until the user requests the next publishing step. Do not use subagents.

## Observed failures

- An existing checkout remains on the v1.1.4 feature branch. Updating its upstream
  reports no changes, but the setup skill still selects v1.1.4 rather than v1.1.7.
- `doctor.dependency_extraction_basis` describes the legacy statement graph, yet
  the agent interpreted it as the limit of all proof dependency extraction.
- A DOI identifies a publication, but the setup prompt does not explain how to
  obtain a supported full-text input before listing theorem/proof evidence.
- The MCPVault worker lacks Git. The prerequisite checker currently marks uv/uvx
  alone as sufficient for the documented Git-source launch.

## First deliverable

1. Add a read-only repository comparison to `scripts/check_onboarding.py`.
   Compare the actual checkout with the local remote-default tracking ref, report
   branch/commit/dirty state, and explicitly state that local refs are not proof
   of remote freshness. Missing Git/refs/timeouts produce structured unknown state.
   The checker never fetches, switches branches, discards edits, or creates worktrees.
2. Update setup guidance and README bootstrap prompts: refresh remote refs, identify
   the remote default branch, and select clean current instructions before trusting
   a release pin. Preserve dirty/development checkouts by using a separate checkout.
   A user-requested historical version remains an explicit exception.
3. Preserve the legacy diagnostic field; add structured statement/proof/input
   capabilities. Proof-local evidence supports source-backed local links and external
   citation blockers, not complete mathematical prerequisites or proof verification.
4. Route DOI-only requests to full-text discovery or a request for a local PDF;
   metadata alone is never reported as imported text. Keep explicit external-reference
   review policy. Preserve existing client configuration/restart boundaries.
5. Require Git as well as uv/uvx for the existing Git-source smoke readiness check.

## Acceptance

- Real temporary Git repositories cover current main, old feature branches with
  dirty files, detached snapshots, missing tracking refs and non-repositories.
- Repository checks leave branch, HEAD, files and dirty status unchanged.
- Diagnostics retain old values while making both extraction surfaces visible.
- Default checker emits repository facts without network calls; smoke readiness
  is false when Git is missing. No checkout is described as latest from local refs.
- Existing deterministic tests and CLI/stdio diagnostics remain compatible.
- Published install examples stay at v1.1.7 until v1.2.0 is actually published.

## Subsequent deliverables

DOI entry will discover public full-text candidates with provenance and explain
unavailable sources; fetching/importing requires the user's reading policy.
Dependency reading will expose source-backed direct and recursive reading order,
clearly separating extracted evidence, missing evidence and outside-paper blockers.
Their exact interfaces are designed after reviewing the existing implementations
and the user's next first-use results.
