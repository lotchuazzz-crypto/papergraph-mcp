# PaperGraph v1.1.2 Reference Import Closure Design

## Goal

PaperGraph v1.1.2 closes the smallest useful loop after Evidence Triage reports an external blocker:

1. identify a blocked external reference from existing evidence;
2. let the user confirm what that reference is;
3. persist the confirmed target with provenance;
4. import and process the target when the user supplies an importable source;
5. regenerate local reading artifacts so the original paper and the newly imported paper can be read together.

This release does not perform online search. It prepares the model and workflow for later search-backed resolution without making PaperGraph guess.

## Context

v1.1.1 Evidence Triage made sparse dependency evidence and blocked external references visible. In first-use output, a reader can now see that references such as `[17]` and `[3]` are blockers, but PaperGraph still cannot act on the user's knowledge that `[17]` is a specific paper.

The existing External Import Planner can already classify:

- `import_candidate` when stored bibliography evidence contains an arXiv ID;
- `already_imported` when that arXiv paper is already in the workspace;
- `blocked` when no arXiv ID is known.

The missing loop is not web search. It is a user-confirmed bridge from `blocked` to a durable bibliographic target, plus import when an actual source is available.

## Users

- A first-time user reading a PDF who sees blocked references in Evidence Triage.
- An MCP-capable reading agent that asks the user to identify a blocked citation and then continues the project.
- A CLI user who knows that `[17]` is an arXiv paper, a local PDF, a DOI, or a published citation and wants that fact recorded before the next reading pass.

## Design Principle

The feature is **Reference Resolution / Import Closure**, not an arXiv-only resolver.

arXiv is one importable source. Local PDF is another. DOI, URL, and published metadata are valid confirmed targets even when PaperGraph cannot import them yet.

## Scope

### In Scope

- Persist user-confirmed resolutions for external blocked references.
- Support these confirmed target kinds:
  - `arxiv`: importable through existing arXiv import flow;
  - `pdf`: importable through existing local PDF import flow;
  - `doi`: confirmed bibliographic target, not automatically downloaded;
  - `url`: confirmed bibliographic target, not automatically downloaded;
  - `metadata`: title/authors/year/venue style confirmation, not automatically downloaded.
- Preserve provenance:
  - original `blocked_id`;
  - citation keys;
  - raw citation and bibliography text;
  - local paper/result/proof context;
  - user-supplied target fields;
  - resolution status and import status.
- Add a read API that reports all reference resolutions for a paper.
- Add an apply API that optionally regenerates:
  - the source paper Reading Report;
  - the imported target paper Reading Report when import happens;
  - a Cross-Paper Reading Plan for source and imported target.
- Surface resolved blockers in Evidence Triage and Reading Reports.
- Expose MCP and CLI entry points.
- Keep all behavior deterministic in tests; no live network search tests.

### Out Of Scope

- Online search across Crossref, Semantic Scholar, OpenAlex, Google Scholar, publisher pages, DOI landing pages, or arXiv search.
- Automatic PDF download from DOI or URL.
- Guessing a reference identity from partial bibliography text.
- Theorem-level matching between the source paper's cited theorem and the imported paper's extracted theorem list.
- Recursive literature crawling.
- Modifying existing evidence rows to pretend the original extraction contained metadata it did not contain.

## Core Concepts

### Reference Blocker

A reference blocker is an existing external import planner blocked item:

```json
{
  "blocked_id": "external-import:blocked:abc123",
  "reason": "missing_arxiv_id",
  "evidence": [...]
}
```

v1.1.2 does not invent a new blocker source. It consumes planner blocked items and stores user-confirmed resolutions against stable `blocked_id` values.

### Resolution Status

A resolution records the user's confirmed target:

- `resolved_imported`: target was importable and PaperGraph imported it;
- `resolved_not_imported`: target is known, but no importable source is available yet;
- `failed_import`: target looked importable but import failed without mutating the existing imported target state.

### Target Kind

Target kind determines import behavior:

- `arxiv`: requires `arxiv_id`; optional `arxiv_version`; imports to `paper_id = "arxiv:<id>"`.
- `pdf`: requires local `path`; optional `paper_id`; imports to supplied `paper_id` or deterministic `local:<slug>`.
- `doi`: requires `doi`; stores confirmation only.
- `url`: requires `url`; stores confirmation only.
- `metadata`: requires at least one of `title`, `authors`, `year`, or `venue`; stores confirmation only.

## Public API

### Workspace Python API

Add:

```python
def resolve_external_reference(
    self,
    paper_id: str,
    blocked_id: str,
    target: dict,
    *,
    import_target: bool = True,
    artifact_dir: str | Path | None = None,
) -> dict: ...

def list_external_reference_resolutions(
    self,
    paper_id: str | None = None,
) -> dict: ...
```

`target` shape:

```json
{
  "kind": "arxiv" | "pdf" | "doi" | "url" | "metadata",
  "arxiv_id": "2401.12345",
  "arxiv_version": "v2",
  "path": "D:/papers/ref17.pdf",
  "paper_id": "local:ref17",
  "doi": "10.1000/example",
  "url": "https://publisher.example/paper",
  "title": "Published paper title",
  "authors": ["Ada Lovelace", "Emmy Noether"],
  "year": "2020",
  "venue": "Journal Name"
}
```

Only fields relevant to the chosen kind are required. Extra fields are preserved as user-supplied metadata when safe to serialize.

Return payload:

```json
{
  "resolution_schema_version": 1,
  "resolution_id": "reference-resolution:...",
  "source": {
    "paper_id": "local:source",
    "blocked_id": "external-import:blocked:abc123",
    "evidence": [...],
    "review": {
      "citation_keys": ["17"],
      "raw_texts": ["By [17, Theorem 2.1]"]
    }
  },
  "target": {
    "kind": "doi",
    "doi": "10.1000/example",
    "title": "Published paper title",
    "authors": ["Ada Lovelace"],
    "year": "2020",
    "venue": "Journal Name"
  },
  "status": "resolved_not_imported",
  "import": {
    "attempted": false,
    "paper_id": null,
    "reason": "target_not_importable_without_local_source"
  },
  "artifacts": [],
  "warnings": []
}
```

For `arxiv` or `pdf` with `import_target=True`, `import.attempted` is true. On success, `import.paper_id` is populated and artifacts may be written if `artifact_dir` is supplied.

### MCP Tools

Add:

- `workspace_resolve_external_reference(paper_id: str, blocked_id: str, target: dict, import_target: bool = True, artifact_dir: str | None = None) -> dict`
- `workspace_list_external_reference_resolutions(paper_id: str | None = None) -> dict`

The tools require an active workspace and convert workspace validation/import errors into `ToolError`.

### CLI Commands

Add:

```powershell
papergraph-mcp resolve-external-reference `
  --workspace .\papergraph.sqlite3 `
  --paper-id local:source `
  --blocked-id external-import:blocked:abc123 `
  --arxiv 2401.12345 `
  --artifact-dir .\papergraph-starter

papergraph-mcp resolve-external-reference `
  --workspace .\papergraph.sqlite3 `
  --paper-id local:source `
  --blocked-id external-import:blocked:abc123 `
  --pdf .\ref17.pdf=local:ref17 `
  --artifact-dir .\papergraph-starter

papergraph-mcp resolve-external-reference `
  --workspace .\papergraph.sqlite3 `
  --paper-id local:source `
  --blocked-id external-import:blocked:abc123 `
  --doi 10.1000/example `
  --title "Published paper title" `
  --year 2020

papergraph-mcp list-external-reference-resolutions `
  --workspace .\papergraph.sqlite3 `
  --paper-id local:source
```

The CLI must reject ambiguous target input. Exactly one of `--arxiv`, `--pdf`, `--doi`, `--url`, or metadata-only `--title/--author/--year/--venue` is accepted.

## Persistence

Add a schema migration for a new table:

```sql
CREATE TABLE reference_resolutions (
    resolution_id TEXT PRIMARY KEY,
    source_paper_id TEXT NOT NULL REFERENCES papers(paper_id) ON DELETE CASCADE,
    blocked_id TEXT NOT NULL,
    target_kind TEXT NOT NULL,
    target_json TEXT NOT NULL,
    status TEXT NOT NULL,
    imported_paper_id TEXT REFERENCES papers(paper_id) ON DELETE SET NULL,
    evidence_json TEXT NOT NULL,
    review_json TEXT NOT NULL,
    artifact_json TEXT NOT NULL,
    warning_json TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(source_paper_id, blocked_id, target_kind, target_json)
);
```

The stored `evidence_json` is a snapshot of the blocked planner evidence at resolution time. This avoids losing provenance if later imports update the workspace.

Use deterministic timestamps in tests through the existing workspace import timestamp pattern where possible. If the existing workspace always uses runtime timestamps for mutations, tests should assert shape and ordering rather than exact wall time.

## Data Flow

### Resolve ArXiv Target

1. Recompute `workspace.plan_external_imports_for_paper(paper_id)`.
2. Find `blocked_id` in `blocked`.
3. Validate `target.kind == "arxiv"` and `arxiv_id` syntax.
4. Persist a resolution snapshot with `status = "resolved_not_imported"` before import attempt.
5. If `import_target=True`, call the existing arXiv import path.
6. On success:
   - update resolution to `resolved_imported`;
   - set `imported_paper_id`;
   - if `artifact_dir` is supplied, write source report, target report, and cross-paper plan.
7. On import failure:
   - keep the resolution row;
   - set `status = "failed_import"`;
   - return the error in `warnings`;
   - do not remove or overwrite existing papers.

### Resolve PDF Target

1. Recompute the source paper import plan and locate `blocked_id`.
2. Validate the local PDF path exists and is a file.
3. Choose target paper ID:
   - supplied `paper_id`, normalized and validated;
   - otherwise deterministic `local:<slug>` from file stem and blocked id.
4. Persist resolution snapshot.
5. Import through existing PDF workspace path.
6. Generate optional artifacts exactly as for arXiv.

### Resolve DOI / URL / Metadata Target

1. Recompute the source paper import plan and locate `blocked_id`.
2. Validate required fields for the target kind.
3. Persist resolution with `status = "resolved_not_imported"`.
4. Return `import.attempted = false` and reason:
   - `target_not_importable_without_local_source`.
5. Evidence Triage and Reading Report must show that the blocker is resolved but not imported.

## Artifact Generation

When `artifact_dir` is supplied and import succeeds:

- write `source-reading-report.md` using the source paper ID slug;
- write `target-reading-report.md` using the imported paper ID slug;
- write `reference-closure-plan.md` as a Cross-Paper Reading Plan over `[source_paper_id, imported_paper_id]`;
- include paths in `artifacts`.

If artifact generation fails after import succeeds, the resolution remains `resolved_imported` and the failure is returned as an artifact warning. The imported paper is not rolled back.

## Evidence Triage And Reports

Evidence Triage gains a `resolved_external_references` summary:

```json
{
  "resolved_imported_count": 1,
  "resolved_not_imported_count": 2,
  "failed_import_count": 0
}
```

Reading Reports render a short subsection under External Import Plan:

- `Resolved and imported`: confirmed target and imported paper ID.
- `Resolved, not imported`: DOI/URL/metadata target and the missing source action.
- `Failed import`: target and error summary.

Blocked items remain visible until the planner itself can prove they are no longer blocked. A user-confirmed resolution supplements extraction evidence; it does not rewrite the original extraction.

## Error Handling

- Unknown `paper_id`: workspace error.
- Unknown `blocked_id`: workspace error naming the source paper and blocked ID.
- Ambiguous CLI target flags: command exits with JSON error payload.
- Unsupported target kind: workspace error.
- DOI/URL missing required value: workspace error.
- PDF path missing or not a file: workspace error.
- arXiv import failure: resolution is retained with `failed_import`.
- Duplicate resolution with identical target: return existing row with `status` and `import` state instead of creating another row.

## Determinism

- `resolution_id` is derived from `source_paper_id`, `blocked_id`, target kind, and canonical target JSON.
- list results sort by `source_paper_id`, `blocked_id`, target kind, then `resolution_id`.
- artifact file names are derived from normalized paper IDs and target kind.
- target JSON is stored with sorted keys.

## Release Notes Shape

Release as `v1.1.2`.

Emphasize:

- user-confirmed reference resolution;
- arXiv and local PDF import closure;
- DOI/URL/published metadata recording for non-importable references;
- regenerated reading artifacts after successful import;
- no online search yet.

Avoid claiming:

- automatic reference discovery;
- publisher PDF download;
- semantic theorem matching;
- recursive literature crawling;
- proof verification.

## Acceptance Criteria

v1.1.2 is ready when:

- a blocked reference can be resolved to an arXiv ID and imported;
- a blocked reference can be resolved to a local PDF and imported;
- a blocked reference can be resolved to DOI/URL/metadata and recorded as `resolved_not_imported`;
- list APIs return persisted resolution history with provenance;
- Reading Reports and Evidence Triage distinguish blocked, resolved-not-imported, and resolved-imported states;
- CLI and MCP entry points cover resolve/list flows;
- focused tests and the full deterministic suite pass;
- v1.1.2 docs clearly state that online search is future work.
