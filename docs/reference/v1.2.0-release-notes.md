# PaperGraph v1.2.0 — DOI Inputs and Evidence-Based Reading

Status: the v1.2.0 Git tag is available and its public pinned installation has been
verified. The separate GitHub Release page is still pending. Active installation
examples on main pin v1.2.0; the immutable tag retains its preparation-era examples.

PaperGraph v1.2.0 improves first-use diagnostics, adds a usable entry for published
DOI papers, and makes proof-local reading paths easier to inspect without claiming
complete mathematical dependency extraction.

## Highlights

- Read-only repository checks distinguish an old feature branch from the local
  default-branch revision, preserve existing changes, and disclose unverified
  freshness. Git-source startup checks Git, uv and uvx; diagnostics separate the
  legacy statement graph from proof-local capabilities.
- DOI discovery separates exact identity, provider metadata, public full-text
  candidates and actual import status. A requested root with one eligible public
  PDF can load under the user's reading policy; competing candidates require
  selection. Provider failures, conflicting identities, unavailable bodies and
  reported versions remain visible, with a local-PDF fallback.
- Dependency reading lists source-backed main-result candidates or uses an
  explicit user target, separates direct/recursive proof-local evidence from
  statement references, and orders shared prerequisites before their dependents.
  Cycles block a claimed prerequisite order; unknown labels and external stops
  remain visible.
- Explicit author-declared introductory correspondence can locate a proof while
  retaining both result nodes and the actual proof owner. It records a declaration,
  not verified mathematical equivalence.
- PDF statements retain bounded adjacent blocks and source locations. Results,
  proofs, contexts and reports expose unverified completeness and continuation
  locators; adjacent context is not automatically proof evidence. Formal headings,
  grouped bibliography entries and nested citation evidence remain distinct from
  discussion mentions and metadata display titles.
- Author-list compatibility now requires complete one-to-one matching. Partial
  overlap is reported separately and cannot earn a full-author match score or
  promote automatic selection. CLI, MCP initialization and diagnostics share the
  package version and expose build-time source provenance for installed wheels.

## Compatibility

Workspace schema remains at version 9; no new runtime dependency is added. Existing
statement-graph fields and resolver history remain available. New reading and PDF
coverage fields are additive. Corrected prerequisite orders may differ from the
old reversed-preorder output; `top_down` remains an exploration route, and cycles
return an empty `bottom_up` with explicit cycle evidence.

DOI metadata and an open-location report are not proof of full-text availability,
content identity, or equality between published and preprint versions. Newly
discovered external references still require a reviewable import plan and are not
automatically downloaded by DOI discovery or dependency reading. PaperGraph does
not bypass paywalls, infer hidden mathematical prerequisites, or verify proofs.
Missing proofs/labels and bounded PDF excerpts remain unresolved or unverified.
The public-PDF downloader checks HTTPS addresses/redirects and caps bodies at
50 MiB; synchronous DNS cannot be hard-interrupted by its elapsed budget.

## Install

These commands install the available immutable Git tag:

```text
uvx --from git+https://github.com/lotchuazzz-crypto/papergraph-mcp.git@v1.2.0 papergraph-mcp --version
uvx --from git+https://github.com/lotchuazzz-crypto/papergraph-mcp.git@v1.2.0 papergraph-mcp doctor
```

Use the locked checkout or an isolated locally built wheel for development tests.
Workspaces and cached papers stay outside the Git repository. Release notes follow
the recent GitHub-release format; no additional distribution channel or asset
upload is introduced.
