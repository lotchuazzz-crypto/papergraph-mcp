# v1.2.2 — reading evidence repairs (public PyPI verified)

PyPI 1.2.2 is published, and the actual public files plus fresh Git-free index
consumers have passed [version-specific acceptance](v1.2.2-publication.md).
Current main enables the PyPI setup gate after that evidence. The public Git tag
matches R; both public GitHub Release assets match the approved PyPI bytes and
passed embedded-source verification. Immutable R/tag/package
files keep their historical prepared-state guidance. Prior tags and bytes are unchanged.

The [first five candidates](v1.2.2-rejected-candidate.md) failed combined independent
acceptance and are withdrawn. Passing code tests, CI and package byte identity
did not establish proof ownership or factual consistency of every consumer
document. The replacement freezes all fixes and consumer instructions into a
new package source R. That final source passed both independent groups before
normal protected publication.

## Changes

1. PDF source slices expose stable raw-block locators and `source_reading`.
   `workspace_read_source_blocks(span_id, limit=20)` (CLI `read-source-blocks
   --workspace DB --span-id ID --limit 20`) returns 1..50 complete original blocks
   and an executable `next`, including for old null-ID imports. Long proofs are
   readable without later result anchors. Raw navigation does not establish
   ownership or formal dependencies.
   New automatic proof evidence retains only the first physical line carrying
   the explicit Proof heading. An unnamed proof requires a directly preceding result span;
   intervening unattributed source leaves its owner unknown. Explicit unique
   names remain supported only when the complete heading names one goal.
   Compound/alternative or unsupported goals remain unowned, without a nearest
   result fallback. All mention extraction uses the body after that same heading
   boundary: goals in a heading are not dependencies. Nested brackets/quotes
   keep their punctuation inside the heading. Unbalanced structures or unsupported
   heading syntax leave body references unknown; known body citations remain
   available even when an annotated heading has no owner. It does not join later lines/blocks using title
   blacklists, font sizes, proximity, budgets or a later QED. A line over 12,000
   characters retains only its heading. The first QED/square position clips the
   line; ambiguous mentions stop without declaring closure or looking for a
   later marker. A subsequent proof heading also stops the excerpt. Thus short
   explicit proof evidence remains available; long-proof late references remain
   unknown and require raw review. This capability limit is deliberate.
   Strict substrings are persisted as `pdf_proof_fragment` source rows with
   stable IDs and exact block-relative offsets. The original raw block is
   unchanged; its bbox is a container, not exact glyph reconstruction. Raw
   pagination excludes these derived rows and bibliography entry rows, resolving their locators back to
   the unique containing original block. No schema migration is introduced.
   New method names and `automatic_ownership_policy` distinguish the policy from
   legacy stored excerpts, which remain unverified without silent rewriting.
   Neither a one-line excerpt nor an explicit marker verifies mathematical
   completeness or all possible PDF layouts.
2. Ordinary `definition of` is not a numbered reference. Digit-bearing numbers,
   uppercase single-letter numbers and explicit TeX labels remain supported.
   Internal unresolved mentions retain their raw text, IDs and span provenance
   under `unresolved_local_mentions`; they do not request an external arXiv ID.
   External citation and external-result evidence remains import-planning input.
3. MCP schemas declare strict integer context 0..5, raw-page limits 1..50,
   map/reading/report candidate limits 1..20 and positive reference-search limits,
   consistent with runtime validation. CLI source context has the same bounds.
4. Plans add `blocked_groups`, `unique_blocked_targets`,
   `unique_external_targets`, `evidence_records` and internal-mention counts.
   Triage uses one blocker/action per exact source-paper/citation-key identity;
   every group retains its legacy `blocked_ids` and all distinct evidence IDs.
   `blocked` and `blocked_count` preserve legacy record semantics and resolution
   compatibility. Unknown identities are not fuzzily merged. Selected dependency
   reading supports opt-in `detail=compact` / `--detail compact`, omitting the
   repeated catalog and source bodies with executable full-evidence accessors.
   `full` remains the default. New search/candidate IDs use SHA-256 digests;
   stored legacy snapshots and decisions are unchanged.
   Compact full-evidence handles preserve the requested candidate limit as well
   as the direct/recursive mode.
5. Doctor recommends the PyPI package pin by default and reports optional Git
   source separately, without a missing-Git warning for PyPI consumers. README,
   setup skill and client recipes distinguish current verified PyPI 1.2.2,
   immutable R's prepared-state snapshot and historical 1.2.1 publication.
   CLI examples identify positional versus flag arguments.
   Existing tutorials, contracts and historical release links remain available.
   Repository text and embedded build manifests use LF on all platforms for
   stable source digests. Release artifacts use the protected Linux build;
   ZIP creator OS metadata distinguishes otherwise identical Windows wheels.
   The actual installed-reference CI smoke asserts the current package and MCP
   version, default PyPI pin and optional Git source, then exercises both CLI
   and stdio snapshots. Local Git prerequisites leave publication unverified;
   explicit live tag verification requires a reviewed expected source commit.
   Preparation contracts check every setup Markdown reference and README for
   contradictory publication claims, channel-specific gates, historical-evidence
   attribution and stale source SHA literals in consumer recipes. The complete
   client recipe gates every installation route before its native commands;
   it obtains source R from the reviewed artifact record instead of copying a
   prior release's SHA. Publication closeout changes main only after acceptance.

## Data compatibility

No workspace schema migration is introduced. Raw navigation works immediately
on existing evidence rows. Improved extraction affects new imports; choose a
reimport explicitly to refresh stored proof evidence. The existing reimport
preservation tests cover reading sessions, notes, checkpoints and queues. Never
overwrite the user's only workspace for acceptance; use a SQLite backup/copy.
External references remain reviewable plans, with no automatic downloads.
Reimport can retire earlier search snapshots and mark preserved decisions for
review under the existing contract; read compatibility does not promise every
search snapshot survives a chosen reimport. Back up before that separate action.

## Verification and release gates

The [prepared artifact record](v1.2.2-artifact-verification.md) fixes package source
R, source-tree digest and both distribution hashes. R is separate from its
release-binding configuration commit.

The [acceptance matrix](../v1.2.2-acceptance.md) describes each repair and its
failure regression. Run `uv sync --locked --dev`, then
`uv run pytest -q -p no:cacheprovider --basetemp <NEW_TASK_TEMP>` on a clean
checkout. Run the installed CLI/stdio smoke outside the checkout for both wheel
and sdist; record source commit, source-tree digest and both artifact hashes.

After the immutable implementation commit exists, a separate release-binding
commit pins the preparation checkout, artifact verifier, no-Git smoke and
publisher to that source and its exact distribution hashes. That binding is
reviewable and does not grant publication approval. Publication must use the
manual main-only workflow and protected `pypi` environment; the same-run artifact
ID, byte hashes, version and embedded source manifest must all match after
approval. Independent acceptance comes before dispatching publication.

After publication, run the separate public-index workflow with a fresh cache
and a genuinely Git-free Linux container; record its immutable run, validate
both first-use routes against the packaged source, then update publication
status in a later documentation/checker commit. A local wheel installation is
not official-index acceptance. Never advance the guard to make testing pass.
