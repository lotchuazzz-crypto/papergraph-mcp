# v1.1.1 Evidence Triage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic Evidence Triage to v1.1 Reading Reports and Workspace Starter artifacts so first-time users can act on sparse dependency output without mistaking extraction limits for mathematical facts.

**Architecture:** Create `src/papergraph/evidence_triage.py` as the small analysis/rendering boundary. `reading_report.py` consumes it and exposes `evidence_triage`; `starter.py` reuses report triage for `START_HERE.md` and manifest payloads. Docs and examples teach triage-first reading, while v1.1.2 reference-resolution search is recorded as future scope.

**Tech Stack:** Python 3.10+, existing `Workspace` API, pytest, deterministic Markdown/JSON artifacts, no new runtime dependencies.

## Global Constraints

- Release version target is `v1.1.1`.
- Do not use subagents.
- Use TDD: no production code before a failing test.
- Do not add theorem/proof extraction logic.
- Do not add database schema changes.
- Do not add network search or automatic external paper import in v1.1.1.
- Do record online reference search and iterative literature import as the v1.1.2 development focus.
- Candidate starts must not be rendered as mathematical recommendations.
- Empty dependencies must remain scoped extraction results, not mathematical independence claims.
