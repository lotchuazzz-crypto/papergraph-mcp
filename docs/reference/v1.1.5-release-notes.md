# v1.1.5 Release Notes (preparation)

This is an unreleased development build. No tag, push, merge or release is
implied by these notes. Use `uv run papergraph-mcp` from the checkout until the
reviewed v1.1.5 tag is published.

## Changes

- Evidence-preserving bibliography hints and conservative DOI/arXiv normalization.
- Deterministic identity grouping, explicit field conflicts and source availability.
- Provider outcomes distinguish empty results from failures; diagnostics omit raw
  exception URLs and headers, and malformed siblings do not erase valid records.
- Saved v2 assessments explain confidence and automatic-selection decisions in
  Workspace, CLI, MCP, Reading Reports and expansion reports.
- New expansions use `unique_strong_v2`; existing `unique_strong_v1` tasks retain
  legacy matching and their budgets/decisions. Policy versions cannot be changed
  mid-run. Hidden competing identities, reported withdrawal/retraction and
  unresolved conflicts block automatic selection.

## Compatibility and boundaries

Back up SQLite workspaces before migration to schema 9. Older versions cannot
open schema 9. Migration preserves historical search/candidate IDs, payloads and
resolution records; v1 rows are not reranked. Refresh creates a new snapshot.

Scores are not probabilities; metadata agreement is not independent verification.
DOI-only metadata is not importable. Missing sources do not establish a paywall;
provider failure does not establish nonexistence. This does not verify proofs,
infer mathematical prerequisites, bypass paywalls or enable unlimited crawling.

Actual Codex, Claude and AutoClaw clients remain `documented_not_run` in the
[compatibility matrix](client-compatibility.md); protocol subprocess tests are
not client-UI validation. Offline acceptance and local verification are recorded
in the implementation plan. Cross-platform CI is a release gate after an
authorized push, not a result claimed by this local preparation.
