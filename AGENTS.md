# Repository instructions

For normal PaperGraph development requests, follow the repository's usual workflow; no onboarding skill is required.
<!-- Keep: ordinary development should not be blocked by installation-specific checks and approvals. -->

When a user asks to install, initialize, configure, set up, or start using PaperGraph with an agent or MCP client, read `.agents/skills/setting-up-papergraph/SKILL.md` completely before responding and follow that skill for the setup conversation.
For an existing checkout, first verify the remote default revision after fetching; an old feature branch can contain obsolete setup instructions even when its own upstream is current. Preserve local changes and branches, using a separate clean checkout for current instructions when needed. Disclose failed freshness checks instead of claiming the checkout is latest. Honor an explicitly requested historical version.
