# PaperGraph v1.2.1 — First-use Evidence and Workflow Repairs

This patch makes extracted proof and bibliography evidence traceable to its
original files and corrects the first-use commands and planning contracts.
Package-version output alone does not establish publication; source identity,
reviewed artifact hashes and official-index acceptance are separate checks.

## Repairs

- Ordinary TeX proof citations preserve optional locators, multiple keys and
  repeated occurrences. Resolved citation evidence is visible to result/queue
  import plans, with result/proof IDs and source spans retained.
- BibTeX evidence points to the parsed top-level entry with matching identity
  fields, rather than a similar key inside a comment or another field.
- Theorem and proof bodies in nested input files map to original-file character
  offsets. Cross-file bodies retain ordered fragments; missing or inconsistent
  mappings fail explicitly. Short TeX excerpts preserve their original whitespace.
- An explicit PDF heading such as `Proof of 2.17` links to a uniquely numbered
  extracted result. Missing or ambiguous targets remain unresolved.
- Generated and static reading commands use current command-first CLI syntax,
  explicit IDs and shell-specific path quoting. Local TeX examples name the main
  `.tex` file. Checkpoints use the accepted `result_id` target kind.
- Starter planning performs read-only file preflight without creating a database,
  parent directories or artifacts. `ready` reports preflight, not successful
  parsing/import; bootstrap performs the writes and imports.
- Result-list schemas expose `limit` 1..100 and nonnegative `offset`; successive
  stable pages are required to establish a complete result listing. Checkpoint
  and note schemas expose their accepted target-kind enums.

## Compatibility and boundaries

Workspace schema remains 9 and runtime dependency requirements are unchanged.
Previously imported affected TeX evidence needs reimport to regenerate its source
spans; user databases are not automatically migrated. Result-list return shape
remains a list, with additive offset support.

Citation evidence supports reviewed import candidates; it does not establish
mathematical dependencies, verify proofs or authorize external downloads. Shared
diamond dependencies retain both `via_mentions`; cycles block local prerequisite
ordering, queues remain exploration routes, and session/checkpoint/note/queue
recovery retains regression coverage. DOI/provider metadata and incomplete PDF
text remain subject to their existing evidence boundaries.
